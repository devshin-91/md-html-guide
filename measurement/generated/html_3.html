결정해야 할 항목사람이 고르거나 승인해야 하는 것
확인된 것 / 확인되지 않은 것무엇이 검증됐고 무엇이 아직인지

1

원본과 구조

뷰는 원본의 사본이고, 사람이 할 일이 먼저다

원본이 아니라 뷰다

뷰와 원본이 다르면 원본이 맞다. 뷰를 직접 고치지 말고 원본을 고친 뒤 다시 만든다.

할 일뷰에 원본 파일과 날짜(또는 커밋)를 적는다.

맨 위에는 AI의 결론이 아니라 사람이 할 일을 둔다

결정해야 할 항목, 확인된 것과 확인되지 않은 것, 이 화면이 다루지 않은 것을 먼저 보여준다.

소제목은 그 섹션 내용을 요약하게 쓴다.

범위MD에도 똑같이 적용된다.

짧게

상위 요약이 긴 상세 자료보다 이해를 도왔고, 과도한 문서는 오히려 이해를 방해했다.

2

사람이 판단하게 만들기

가정을 확인하게 하고, 사람 판단을 먼저 받고, 결과를 돌려준다

AI 계획에는 "이 계획의 가정" 섹션을 두고 사람이 하나씩 확인하게 한다

근거AI가 만든 계획을 검토할 때 가정을 찾게 하자 과신이 가장 많이 줄었고 부담은 늘지 않았다.

가능하면 AI 추천보다 사람의 판단을 먼저 받는다

근거억지로 생각하게 만드는 설계가 단순 설명보다 과신을 크게 줄였다.
주의가장 인기가 없었으니 중요한 결정에만 쓴다.

고른 결과는 export한다

JSON·MD·프롬프트로 복사해 에이전트에게 돌려준다.

3

설명과 표시 방식

설명보다 검증 경로, 조언보다 판단 정보

설명을 더 붙이는 것으로 검토가 나아지지 않는다

근거AI 설명은 맞든 틀리든 수용만 늘렸다. 설명이 과신을 줄인 건 검증 비용을 낮출 때뿐이었다.
할 일주장마다 근거(코드 줄, 출처 링크)로 바로 가서 하나씩 확인할 수 있게 한다.

AI가 만든 부분과 사람이 확인한 부분을 나눠 표시한다

주장마다 검증됨 / 미검증이나 신뢰도를 붙이고, 해결되지 않은 불확실성을 드러낸다.

근거항목별 신뢰도 표시는 적절한 의존을 늘렸다.

AI의 조언을 가장 눈에 띄게 두지 않는다

근거눈에 띄게 보여준 조언은 틀려도 더 따랐고, 세부 정보가 지나치게 많으면 덜 신중해졌다.
할 일"이렇게 하라"는 권고보다 판단에 필요한 정보를 보여준다.

보기 좋은 것과 맞는 것을 구분한다

깔끔한 화면, 정돈된 PR 설명은 품질 신호가 아니다. 도구가 템플릿으로 찍어 내는 경우가 많다.

4

누락

AI가 놓친 것은 화면에 없으니 범위를 적는다

"이 화면이 다루지 않은 것"을 꼭 적는다

근거AI가 짚어 준 곳만 보게 되기 쉽고, AI가 놓친 것은 숙련자도 그대로 따라갔다.
할 일중요한 변경은 원본 diff로 직접 확인한다.
5

만들 때

필요할 때만, CSS는 공용으로, 오픈 모델은 내용 먼저

필요할 때만 만든다

HTML은 생성 시간과 토큰이 더 든다. 사람이 실제로 보고 판단할 산출물에만 쓴다.

여러 뷰를 만들면 CSS를 공용 파일로 뺀다

근거HTML 토큰의 절반 가까이가 CSS다.

오픈 모델이면 내용을 먼저 쓰게 한다

근거오픈 모델은 형식 지시만으로 추론이 떨어졌고, 내용과 서식을 나누면 대부분 회복됐다.
참고최신 비공개 모델(Claude 등)에서는 이 손실이 거의 없었다.
체크 상태는 이 브라우저에만 저장된다. 공유하려면 "체크 결과 MD로 복사"를 쓴다.

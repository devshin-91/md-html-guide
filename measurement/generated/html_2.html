원본과 구조 3

뷰는 원본의 사본일 뿐이고, 첫 화면은 사람의 할 일로 시작하며, 짧을수록 낫다.

뷰와 원본이 다르면 원본이 맞다. 뷰를 직접 고치지 말고 원본을 고친 뒤 다시 만든다.

뷰에 원본 파일과 날짜(또는 커밋)를 적는다.

결정해야 할 항목, 확인된 것과 확인되지 않은 것, 이 화면이 다루지 않은 것을 먼저 보여준다.

소제목은 그 섹션 내용을 요약하게 쓴다. MD에도 똑같이 적용된다.

근거 상위 요약이 긴 상세 자료보다 이해를 도왔고, 과도한 문서는 오히려 이해를 방해했다.

사람이 판단하게 만들기 3

가정을 직접 확인하게 하고, 중요한 결정에서는 사람의 판단을 먼저 받고, 고른 결과는 돌려준다.

근거 AI가 만든 계획을 검토할 때 가정을 찾게 하자 과신이 가장 많이 줄었고 부담은 늘지 않았다.

근거 억지로 생각하게 만드는 설계가 단순 설명보다 과신을 크게 줄였다.
주의: 가장 인기가 없었으니 중요한 결정에만 쓴다.

JSON·MD·프롬프트로 복사해 에이전트에게 돌려준다.

설명과 표시 방식 4

설명을 늘리기보다 검증을 쉽게 하고, AI와 사람의 몫을 나누며, 권고보다 판단 재료를 보여준다.

주장마다 근거(코드 줄, 출처 링크)로 바로 가서 하나씩 확인할 수 있게 한다.

근거 AI 설명은 맞든 틀리든 수용만 늘렸다. 설명이 과신을 줄인 건 검증 비용을 낮출 때뿐이었다.

주장마다 "검증됨/미검증"이나 신뢰도를 붙이고, 해결되지 않은 불확실성을 드러낸다.

근거 항목별 신뢰도 표시는 적절한 의존을 늘렸다.

"이렇게 하라"는 권고보다 판단에 필요한 정보를 보여준다.

근거 눈에 띄게 보여준 조언은 틀려도 더 따랐고, 세부 정보가 지나치게 많으면 덜 신중해졌다.

깔끔한 화면, 정돈된 PR 설명은 품질 신호가 아니다. 도구가 템플릿으로 찍어 내는 경우가 많다.

누락 2

AI가 놓친 것은 사람도 놓치기 쉬우므로, 다루지 않은 범위를 적고 중요한 변경은 원본으로 본다.

근거 AI가 짚어 준 곳만 보게 되기 쉽고, AI가 놓친 것은 숙련자도 그대로 따라갔다.

만들 때 3

HTML은 비싸니 필요할 때만, 여러 개면 CSS를 공유하고, 오픈 모델이면 내용부터 쓰게 한다.

HTML은 생성 시간과 토큰이 더 든다. 사람이 실제로 보고 판단할 산출물에만 쓴다.

근거 HTML 토큰의 절반 가까이가 CSS다.

근거 오픈 모델은 형식 지시만으로 추론이 떨어졌고, 내용과 서식을 나누면 대부분 회복됐다. 최신 비공개 모델(Claude 등)에서는 이 손실이 거의 없었다.
왼쪽 테두리가 진한 카드는 첫 화면 구성·판단·누락에 직결되는 항목이다. 체크 상태는 이 브라우저에만 저장된다.
